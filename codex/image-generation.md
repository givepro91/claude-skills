# codex 이미지 생성

`codex exec` 에 빌트인 `image_gen` 이 붙는다(ChatGPT **Plus** 필요). 레퍼런스 이미지를 넣은 편집·스타일 전이도 된다. codex 가 파일을 직접 읽고 직접 저장하므로 브라우저·다운로드·수작업이 필요 없다.

```bash
cat /tmp/codex_prompt_img.md | codex exec \
  -C "$PWD" -s workspace-write --skip-git-repo-check > /tmp/codex-logs/img.log 2>&1
```

## 빌트인 도구가 실제로 받는 것 (2026-09-20 세션 기록 · 생성물 807장 실측)

codex 가 부르는 것은 `image_gen__imagegen({prompt, referenced_image_paths, num_last_images_to_include})` 가 전부다. **모델·크기·품질 인자가 없다** — 프롬프트에 「1024x1024, quality high」라고 적어도 도구에는 안 들어가는 그냥 글이다.

| | |
|---|---|
| **모델** | 서버가 고른다. 로컬에서 확인되는 것은 PNG 속 C2PA 서명 `ChatGPT / gpt-image`(버전 숫자 없음)뿐이다. 출력 특성(임의 비율 · 최대 3:1)은 `gpt-image-2` 규격과 맞고 `gpt-image-1.5` 의 고정 세 크기와는 안 맞는다 — **추정이지 확인이 아니다** |
| **크기** | **늘 약 157만 화소, 비율만 바뀐다.** 1:1 → 1254×1254 · 3:2 → 1536×1024 · 2:3 → 1024×1536 · 2:1 → 1774×887 · 3:1 → 2172×724(가로 상한) · 세로 폰 → 853×1844. 원하는 것은 픽셀이 아니라 **비율**로 적는다 |
| **칸당 해상도** | 시트에 칸을 늘릴수록 준다. 8프레임 한 줄(2172×724) = 칸당 약 271px, 1254² 에 4×4 = 칸당 약 313px. 크게 쓸 그림(대표 그림·층주)은 한 장에 하나 |
| **투명 배경** | **이펙트·소품은 된다(4/4), 인물은 안 된다(0/4)** — 인자가 아니라 프롬프트 글로 요청하고 서버가 정한다(아래) |
| 4K · 품질 지정 | 빌트인으로는 못 한다. API 경로(`gpt-image-2`, 최대 3840px)뿐이고 플랫폼 API 키·별도 과금이다(맨 아래) |

## 프롬프트 양식

```markdown
== 승인 ==
사용자가 이미 승인했다. 질문 없이 구현. 질문하고 멈추면 실패.

== 구현 ==
빌트인 image_gen 도구로 이미지 1장을 생성한다.
- 프롬프트: <전문>
- 입력 이미지: <경로1> = Image 1 (STYLE ONLY), <경로2> = Image 2 (IDENTITY)
- 비율: <정사각 / 가로 3:1 한 줄 / 세로 2:3 …>
- 결과 PNG 를 <출력경로> 로 복사한다. 재인코딩·변환 금지 — cp 로만.
  다른 세션의 generated_images 를 집지 말고 이 세션이 방금 만든 파일만 복사한다.
== 하지 말 것 ==
- 코드(Pillow/canvas/SVG)로 직접 그리는 것 절대 금지. image_gen 도구로만.
- 크기가 달라도 불가 처리하지 말고 그대로 저장해라.
- 실패하면 파일을 만들지 말고 `불가: <에러>` 만 출력해라.
```

생성물은 `<CODEX_HOME>/generated_images/<session>/exec-*.png` 에 먼저 떨어진 뒤 지정 경로로 복사된다. 세션 id 는 로그의 `session id:` 줄에 있다 — 받은 파일과 그 폴더 원본의 `shasum` 이 같으면 제 것이다.

## 투명 배경 (2026-09-20 실측 8장)

**피사체에 따라 갈린다.** 같은 양식·같은 화풍 참조·같은 가드로 뽑았다.

| 피사체 | 비율 | 결과 |
|---|---|---|
| 이펙트 1장(불꽃 베기, 글로우) | 1:1 | 진짜 알파 |
| 이펙트 8프레임 한 줄 | 3:1 | 진짜 알파 |
| 소품 1개(무기 아이콘) | 1:1 | 진짜 알파 — 고리 안쪽 구멍까지 뚫린다 |
| **인물** 걷기 4프레임 | 2:1 · 2:1 · 3:1 | **셋 다 실패** — 알파 없는 RGB 에 **체커보드를 그림으로 그려 넣는다** |
| **인물** 한 명 | 1:1 | **실패** — 같은 증상 |

- **인물에는 투명을 요청하지 않는다.** 그려진 체커보드는 단색 바탕보다 지우기 나쁘다. 인물은 단색 바탕(회색 `#33353a` · 마젠타)으로 뽑아 코드로 지우는 옛 방식을 쓴다.
- 비율은 원인이 아니다(인물은 1:1 · 2:1 · 3:1 다 실패, 이펙트는 1:1 · 3:1 다 성공). codex 가 다시 쓰는 프롬프트에 `Scene/backdrop: transparent` 줄이 있느냐도 원인이 아니다(강제로 넣고도 실패). **왜 인물만 안 되는지는 모른다** — 표본이 적으니 서버가 바뀌면 다시 잰다.
- 성공·실패는 생성 기록의 `transparentBackground` 와 `check-image.py` 의 「투명 %」로 바로 갈린다. 아래 가드 줄을 넣으면 codex 도 실패 때 `투명 아님:` 으로 정직하게 보고했다(4/4).

구현 절에 아래 두 줄을 더한다.

```markdown
**투명 배경(transparent background)으로 요청하고, 생성된 알파 채널을 그대로 보존한다.**
- 도구가 투명 배경을 못 주면 억지로 만들지 말고 나온 그대로 저장한 뒤 `투명 아님: <사실>` 을 보고해라.
```

그리고 그림 프롬프트 끝에: `TRANSPARENT BACKGROUND — no backdrop, no floor, no shadow, no checkerboard pattern, no border, no text. The glow must fade to full transparency, not to white or black.`

성공한 것(불꽃 베기 한 장 기준): 8-bit RGBA, 생성 기록의 `transparentBackground: true`. 네 귀퉁이 알파 0, 글로우는 알파 1~239 로 부드럽게 빠진다(전체의 24.6%). 남색·풀색·흰 바탕에 얹어도 **테두리 색 번짐이 없다** — 반투명 픽셀의 RGB 가 제 색(주황) 그대로인 스트레이트 알파다. 크로마키(마젠타 바탕 → 코드로 지움)가 글로우에서 남기던 분홍 테두리가 원천적으로 없다.

받아 쓸 때 알아 둘 것:

| | |
|---|---|
| **심지가 알파 255 가 아니다** | 불투명해야 할 자리가 240~254 로 온다(255 는 0.0%). 눈에는 안 보이지만 **`알파 == 255` 로 마스크를 뜨는 코드는 통째로 빈다** — 문턱(≥ 200)으로 자른다 |
| **`알파 > 0` 으로 트림하면 캔버스 거의 전부가 잡힌다** | 알파 1~7 의 옅은 안개가 넓게 깔린다(상자 39,17–1253,1254). `알파 > 16` 이면 86,96–1188,1161 로 그림에 붙는다. 트림·덩어리 찾기는 **문턱 16** 부터 |
| **진위 검사는 `check-image.py` 로** | 옛 한 줄 검사는 투명한 빈 자리를 「단일색 블록」으로 세어 진짜를 가짜 쪽으로 민다(이 그림이 690/1521 = 45%, 피사체가 더 작으면 절반을 넘는다) |
| **프레임 한 줄은 등분으로 자르지 않는다** | 8프레임(2172×724)에서 절정 프레임 폭이 343px 로 균등 칸(272px)을 넘었다. 대신 칸 사이가 **알파 0 인 빈 열**이라 `알파 > 16` 의 열 점유로 깨끗이 갈린다. 흩어지는 끝 프레임은 덩어리가 여럿으로 떨어지니(한 프레임이 셋으로) **가까운 칸 중심으로 묶는다** |
| **딱딱한 외곽선도 깨끗하다** | 소품 아이콘을 확대해도 가장자리 번짐이 없다. 글로우를 글로 시켜도 늘 나오지는 않는다(8프레임 시트는 반투명 3.6% 뿐) |
| **미검증** | 격자(4×4 등) 시트, 적·괴물(인물처럼 실패하는지 소품처럼 되는지) |

## 진위 검사 — 반드시 한다

codex 는 image_gen 이 없어도 **코드로 격자를 그려 놓고 "생성 완료"라고 보고한 적이 있다**(2026-08 실측). 파일이 생겼다는 것은 증거가 아니다.

```bash
python3 ~/.claude/skills/codex/check-image.py X.png [Y.png …]   # 가짜가 하나라도 있으면 exit 1
```

고유색이 1000 미만이거나 (통째로 투명한 칸을 뺀) 단일색 블록이 절반을 넘으면 **코드로 그린 가짜다.** 실측 대비: 가짜 = 고유색 2~9 · 단일색 866~968/1024, 진짜 = 고유색 52,481~122,379 · 단일색 0. 투명·반투명 비율도 같이 찍히니 「투명으로 시켰는데 투명 0%」도 여기서 잡힌다.

숫자가 통과해도 **그림은 눈으로 본다** — 내용이 틀린 그림(남의 층주, 얼음 화살이 든 불 아이콘)은 어떤 검사도 못 잡는다.

## 함정

| 증상 | 원인 | 대응 |
|---|---|---|
| `불가: …1254×1254로 생성되어` 등 크기 불일치 불가 보고 | 도구에 크기 인자가 없어 **요청한 픽셀로는 애초에 안 나온다** → codex 가 정직성 가드를 과잉 적용해 **정상 산출물을 스스로 `/private/tmp/` 로 치우고** 불가 보고 (2026-08-19 실측) | 프롬프트에 픽셀 크기를 적지 말고 비율만 적는다. 이미 났으면 로그의 mktemp 경로에서 회수한다 |
| 병렬 두 세션의 산출물 sha 가 같다 | 한 세션이 `ls generated_images/*/*.png` 로 **다른 세션의 파일**을 집어 복사했다 (2026-09-06 실측, 세 번) | 양식의 「이 세션이 방금 만든 파일만」 줄을 빼지 않는다. `shasum` 으로 가르고, 잃은 판은 그 세션의 `~/.codex/generated_images/<session>/exec-*.png` 에서 되찾는다(로그의 `cp` 줄이 어느 파일을 썼는지 말한다) |
| 마젠타 바탕을 지운 뒤 글로우 가장자리에 분홍이 남는다 | 크로마키는 반투명 픽셀에 바탕색이 섞여 들어온다 | 글로우·연기·빛이 있는 것은 투명 배경으로 뽑는다(위) |

REST 폴백(`~/.codex/skills/.system/imagegen/scripts/image_gen.py`, 기본 모델 `gpt-image-2`)은 쓰지 않는다. OAuth 토큰의 `scp` 에 `api.model.*` 이 없어 `api.openai.com` 직접 호출은 401/403 이고, **ChatGPT 플랜을 올려도 안 열린다**(플랫폼 API 키는 별도 상품·별도 과금). 게다가 API 의 `gpt-image-2` 는 `background=transparent` 를 안 받는다 — 투명은 빌트인 쪽이 낫다.
