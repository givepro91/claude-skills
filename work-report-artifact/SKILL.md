# 작업 보고 아티팩트

한 세션의 작업을 원작자가 읽는 한 장으로 만든다. 패치노트의 개발자 노트처럼 읽히고, 그대로 보고서에도 붙는다.
정본 예시: 2026-09-15 「상자가 열린다」(용병단 서바이버 0.3.1). 틀은 `template.html` 이다 — 복사해서 내용만 채운다.

## 언제 쓰나
- 세션 끝에 「작업 보고」「어떻게 됐는지 정리」「아티팩트로」를 요청받았을 때
- 위임받은 작업을 끝내고 결과를 넘길 때 (질문 없이 진행한 일은 여기서 판단 근거를 보여 준다)
- 쓰지 않는다: 코드 리뷰 결과(ReportFindings), 설계 문서, 학습용 해설(web-doc·explain-diff)

## 페이지의 순서 (이 순서를 바꾸지 않는다)
1. **머리띠(masthead)** — 남색 바탕. 눈썹 줄에 `날짜 · 원작자 인용 한 토막 · 과업 id`. 제목(h1)은 **그 세션의 명제** 한 줄(「상자가 열린다」「쓰러진 자리에서 일어선다」)이지 작업 목록이 아니다. 리드 두 문장: 무엇이 문제였고 무엇을 했나. 그 아래 **사실 띠** 4칸(커밋 수·측정값·기기·검사 통과) — 숫자는 여기에만 둔다.
2. **작업 절** — 절마다 `h2 + 회색 태그`(누가 요청했나·어느 화면인가). 원작자 말은 `.quote` 로 **원문 그대로** 인용한다. 본문은 「전에는 → 지금은」 두 문장이면 된다. 캡처는 바뀐 자리만, 캡션에 **기기·조건**을 적는다(「S23 · 오른쪽 아래를 끌자」). 영상·소리는 `<video>`/`<audio>` 로 넣고 「맥 렌더」「실기기」를 캡션에 갈라 적는다.
3. **캡처를 보다 찾아 고친 것** — 부수적으로 고친 것은 따로 절을 둔다. 주 작업과 섞지 않는다.
4. **기기** — `dl.rows` 로 기기·검증마다 한 줄. 상태 알약은 둘뿐: `ok`(최종 빌드로 확인) · `no`(미확인·미측정). **안 본 것은 반드시 `no` 로 적는다** — 한쪽만 보고 「동작한다」고 쓰지 않는다.
5. **남은 것** — 번호 목록. 항목마다 **굵은 이름 + 원작자가 정할 것**을 한 문장으로. 「~할 예정」이 아니라 「정해 주시면 ~하겠다」.

## 문장 규칙 (docs/WRITING_STYLE.md 그대로)
- 목청 가다듬기 금지(「결론부터」「정리하면」), 이항 대조 금지(「A 가 아니라 B」→ B 만), 부사 크러치 금지(정말·확실히·매우).
- 무생물 주어·피동 대신 누가 무엇을 했는지. 「고쳤습니다」「뺐습니다」「쟀습니다」.
- 줄표(—) 대신 마침표나 가운뎃점. 한 문단 세 문장 안팎.
- 숫자는 사실 띠와 표에만. 본문 문장에 측정값을 넣지 않는다.
- 거짓 없는 상태: 못 들은 것·못 본 것·표본이 적은 것은 그렇게 적는다.

## 파일·미디어
- 미디어는 `files` 로 같이 올린다(`media/xxx.jpg`, `media/xxx.mp4`, `media/xxx.m4a`). 폰 캡처는 폭 700 안팎 JPEG, 소리는 `afconvert -f m4af -d aac -b 96000`.
- `<title>` 은 `제품 버전` 또는 `제품 · 주제`(두세 낱말). h1 이 명제를 맡는다.
- favicon 은 그 세션을 대표하는 이모지 하나.

## 흔한 실수
| 실수 | 대신 |
|---|---|
| h1 에 「치료약 구현 및 브금 교체」 | 명제로: 「쓰러진 자리에서 일어선다」 |
| 사실 띠에 「검사 통과」만 | 「1,437 / 1,437 통과」처럼 분모까지 |
| 미검증을 비워 둔다 | `no` 알약 + 왜 못 봤는지 한 줄 |
| 캡션에 「치료약 화면」 | 「393pt · 부상자 둘 · 누르기 전」 |
| 원작자 인용을 다듬는다 | 원문 그대로, 오타도 그대로 |
| 서로 다른 검사를 더해 한 수로(12+1,437=1,449) | 검사마다 이름을 붙여 따로 — 「e2e 12 / 12 · 순수 1,437 / 1,437」 |
